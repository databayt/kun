# Rust in databayt — the Standard and feature colocation

Every databayt repo that adds Rust follows the card at `.claude/patterns/cards/rust.md`. The shape: one crate, Rust sits beside the feature's UI, and the shell stays feature-agnostic. A `crates/` tree is a deliberate non-choice here; colocation beats layer folders.

## Good

```toml
# Cargo.toml
edition = "2024"
rust-version = "1.90"
tauri = "=2.12.5"
tauri-build = "=2.7.5"

[lints.clippy]
pedantic = { level = "warn", priority = -1 }
unwrap_used = "deny"
```

```
src/components/machine/driver/
  rust.rs        # types, logic, #[tauri::command]s, pub fn plugin<R: Runtime>()
  actions.ts     # invoke("plugin:driver|run"), isTauri() guard, no "use server"
  types.ts       # @generated by ts-rs — never hand-edit
```

- Errors: `thiserror` enums in features (impl `Serialize` as the message), `anyhow` only in bins.
- Async `tokio`, logs `tracing`; data `serde` + `rusqlite` locally, `sqlx` only for a Postgres server.
- Spawn child CLIs with `tokio::process`, `kill_on_drop(true)`, and `--` before the prompt.
- Tests: `cargo test`, `insta` snapshots, fixtures captured from the real tool and sanitized.
- CI runs `cargo clippy --all-targets -- -D warnings`; exact `=` pins for tauri / tauri-build.

## Bad

```rust
let out = Command::new("claude").arg(prompt).output().unwrap(); // no `--`, unwrap, blocking
```

- Hand-registering a feature in `lib.rs` or `main.rs` (build.rs does it).
- Hand-editing a generated `types.ts`, or a feature's Rust living outside its folder.
- JS with shell rights, a model proxy, an embedded agent runtime, `--bare`, or the Agent SDK on a subscription login.
- A capability granted to every kun page instead of `/*/machine/*` only.
- `unsafe`, `unwrap()` outside tests, a tauri release under two weeks old, Tauri 3 alpha.

## Fix

Move the Rust into `src/components/machine/<feature>/rust.rs`, expose commands through its `plugin()`, replace `unwrap` with a `thiserror` error, and run `cargo clippy --all-targets -- -D warnings`.
