# Tasks template

The canonical shape of a `/tasks` issue comment. Posted as a comment headed `## Task Breakdown`, rendered as a GitHub checklist grouped by pipeline stage so progress is trackable on the issue.

```markdown
## Task Breakdown

### schema

- [ ] [judge] Add `<Model>` to prisma/schema.prisma with tenant field — verify: `pnpm tsc --noEmit`
- [ ] [build] Create validation.ts Zod schemas — verify: types compile

### code

- [ ] [build] Server actions (create/update/delete) with auth + tenant scope — verify: `pnpm tsc --noEmit`
- [ ] [judge] Authorization rules — verify: unauthorized call rejected

### wire

- [ ] [build] page.tsx (mirror pattern) + content.tsx — verify: route renders
- [ ] [build] form.tsx with useActionState — verify: submit round-trips
- [ ] [build] columns.tsx (if list view) — verify: table renders
- [ ] [build] i18n keys (en + ar) — verify: no hardcoded strings — `pnpm build`

### check

- [ ] [judge] /handover <block> — verify: READY FOR DEMO

---

_Generated by tasks stage. Ready for implementation._
```

Order matters: dependencies first (schema → code → wire). Each task carries its own verify step (the stage's exit gate) and the lane that runs it (`engine.json → lanes`): `[build]` sonnet at medium effort through a build agent, `[judge]` opus at high effort, `[lookup]` Explore on haiku, `[script]` no model.
