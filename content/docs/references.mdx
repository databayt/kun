## How it reaches them

The MCP catalog in `.claude/mcp.json`. `setup.sh` registers a server unless the catalog marks it as documentation only.

| Server | What it is for | Registered by setup |
| --- | --- | --- |
| `airtable` | Airtable data management | no — catalog only |
| `chrome-devtools` | Chrome DevTools Protocol — real-Chrome capture, network/asset waterfall, CSS cascade, performance. Attaches to Chrome on :9222 (chrome-debug.sh) to reuse manual logins, else default persistent profile. (clone --devtools; pinned 1.3.0) | yes |
| `claude-design` | Claude Design (Anthropic Labs) — canvas design-system sync + handoff; auth via /design-login, subscription-covered | yes |
| `context7` | Up-to-date documentation for libraries — the hosted endpoint (keyless; add an Authorization: Bearer header if a Context7 key is ever issued). Was a per-session npx process at @latest until 2026-09-27. | yes |
| `figma` | Figma hosted MCP (OAuth) — works app-open or closed. Free Starter: 20 tool calls/MONTH total — reads AND writes (get_screenshot, get_metadata, use_figma, generate_figma_design) all meter; only add_code_connect_map, create_new_file, whoami are exempt. Budget the whole job before the first call; use window screenshots for everyday design reading. | yes |
| `figma-desktop` | Figma desktop app local MCP (port 3845) — requires app running + 'Enable desktop MCP server' quick-action toggled. Selection-based design context when available. | no — catalog only |
| `filesystem` | Direct file system access | no — catalog only |
| `github` | GitHub repositories, issues, PRs, and Projects | yes |
| `linear` | Issue tracking and project management | no — catalog only |
| `markitdown` | MarkItDown — convert PDF, Office, images, audio, HTML, URLs to Markdown. setup.sh installs it once (uv tool install markitdown-mcp); uvx then reuses that environment. Without the install, uvx built a fresh 369 MB environment on every session start and piled up ~75 copies in ~/.cache/uv (found 2026-09-27). | yes |
| `notion` | Documentation sync, knowledge base | no — catalog only |
| `posthog` | Product analytics, feature flags | no — catalog only |
| `ref` | Search documentation, curated technical docs — pinned: @latest made npx query the registry on every session start. /sync bumps the pin. | yes |
| `sentry` | Error monitoring, debug production issues | no — catalog only |
| `shadcn` | shadcn/ui component registry - browse, search, install components — pinned (was @latest, a registry lookup per session start); /sync bumps it with the shadcn CLI. | yes |
| `slack` | Team notifications, collaboration | no — catalog only |
| `stripe` | Payment processing, subscriptions | no — catalog only |
| `vercel` | Vercel deployments, logs, projects | no — catalog only |

Which servers are actually called, and by whom, is measured rather than assumed: `node .claude/scripts/usage.mjs` counts the calls in the session transcripts.
