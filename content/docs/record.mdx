# Record

The engine films and photographs databayt products **as they actually run** — signup
flows, onboarding wizards, block features — and files every asset into one organized
library that mirrors to Google Drive. Say it in prose: _"record video for school
onboarding"_, _"record admission"_, _"re-record the stale blocks"_.

This is the **product-truth archive**. Generated marketing media never lands here — that
is [higgs](/docs/higgs) + the showroom on the [media](/docs/media) page.
To cut, caption or reframe a take into a reel, hand it to [edit](/docs/edit).

## The library

Raw footage is filed under the same words as every other media asset — the flow name
(`<verb>-<entity>`) that also names the `shoot` flow, the CDN slug and the
product manifest id:

```
~/media/<repo>/<flow>/<flow>[-<part>]-<locale>.<ext>

hogwarts/add-student/add-student-ar.mov
hogwarts/onboarding/onboarding-otp-ar.mov
```

- **Same name = replaced.** A re-record overwrites the take and its `manifest.json` entry
  (repo, block, flow, url, repo sha at capture, date, note) — no `-vN` siblings.
- No `--flow`: the URL slug stands in (scheme/host, locale prefix and `/s/<subdomain>` stripped).
- The **deliverable** (ad cut or edit) goes to `~/<repo>/public/screenshot/<flow>/<flow>-<locale>.mp4`
  and reaches the CDN with `shoot/scripts/publish.mjs --flow <flow>` as `<flow>/video-<locale>`.
- Mirror: **My Drive → databayt → media** (`record.sh sync`; the local library is
  the truth, Drive is the mirror)

## The machinery

| Piece                              | Where                                        |
| ---------------------------------- | -------------------------------------------- |
| Skill (the playbook)               | `.claude/skills/record/SKILL.md`             |
| Agent (the videographer)           | `.claude/agents/record.md`                   |
| CLI (capture/file/sync/stale)      | `.claude/scripts/record.sh`                  |
| Staleness nudge (SessionStart)     | `.claude/hooks/session-media-stale.sh`       |
| Spell                              | `record` — The Pensieve, [keywords](/docs/keywords) |

```bash
record.sh start intro    # begin a screen-recording segment
record.sh stop           # SIGINT + ffprobe verify — never plain kill
record.sh otp            # screenshot the Outlook desktop inbox (off camera)
record.sh assemble x     # concat segments into one .mov
record.sh file <src> --repo hogwarts --block onboarding --url <real-url>
record.sh sync           # mirror to Google Drive
record.sh stale          # what needs a re-record
```

## Flows behind logins and OTPs

Recording real flows means completing them — the engine handles the walls on its own:

- **Fresh identity per take**: `osmanabdout+<take>@hotmail.com` (`+` aliases deliver
  to the same inbox; reusing one collides with prod leftovers from prior takes)
- **Hotmail/Outlook codes**: the signed-in Outlook **desktop app**, read off a
  screenshot — codes are 4 digits. AppleScript cannot read New Outlook's mailbox and
  the automation Chrome profile is logged out of web Outlook; the screenshot lane is
  the one that works
- **Gmail codes**: the Gmail MCP reads them without any screen work
- **Anything else**: the `auth` and `credentials` skills (Keychain identities)

Recording happens in **segments** — stop, fetch the code off camera, resume — so the
inbox never appears in the footage.

## Iterate

The library stays honest by construction: every asset records the repo sha it was
captured at. When a block's source gains commits, the `session-media-stale` hook says
so at session start, and `record.sh stale` lists exactly what drifted. Re-recording
files the same name as the next version; fine-tune a video with an ffmpeg trim,
a screenshot by recapturing the route.

## One-time macOS permissions

| Grant                                   | Enables                          |
| --------------------------------------- | -------------------------------- |
| Screen recording (already granted)      | `screencapture -v`               |
| Full Disk Access for the terminal app   | fast rsync into the Drive folder |
| "Control Finder" automation (or the above) | the Finder copy sync lane     |

Sweeps are serial by design — one screen, one recorder — so there is deliberately no
multi-agent fan-out here; the skill plans the shot list, then works it in order.
