# Connectors

Claude reaches outside services in three ways. The Machine app lists all three on one page,
**Connectors** in the mega menu, laid out like the
[claude.com marketplace](https://claude.com/marketplace/connectors-plugins): a logo, a name, a
badge and one line per card, filtered by category.

| Kind | What it is | Where it is added |
|---|---|---|
| **Connector** | A remote MCP server signed in through claude.ai | Claude desktop → Settings → Connectors. It then reaches Claude Code too, as `claude.ai <Name>` |
| **Plugin** | A Claude Code bundle: skills, agents, and usually an MCP server | `/plugin` in Claude Code, from a marketplace such as `claude-plugins-official` |
| **Local MCP** | A server kun registers on the machine | `.claude/mcp.json` is the catalog. `setup.sh` runs `claude mcp add` for each one, and the Machine app switches them on and off under `.claude → mcp` |

The list in the app lives in `machine/src/components/plugins/registry.ts`. Edit it there and
update this page with it. "Installed" on a card means one of its names shows up in `claude mcp list`.

## Authentication

- **Connectors and plugin servers** sign in with OAuth. A server that shows `Needs authentication` in `claude mcp list` needs `/mcp` in Claude Code, or one click in Claude desktop.
- **Local servers** read keys from the Keychain through the [credentials](/docs/credentials) lane and the central `.env`. Keys are never written into `mcp.json`.
- **Remove a server you don't use; don't just disable it.** An unused server still costs context on every session.

See [MCP](/docs/mcp) for how servers load, and [Interconnection](/docs/interconnection) for how a keyword reaches the right one.
