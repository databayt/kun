## Config — Universal

Every machine gets the **full config**: all agents, all skills, the full MCP fleet, all hooks (live counts in `.claude/engine.json`). Role is a label and a _secrets-trust tier_ — it never limits what the machine can do.

What varies is **which API keys a machine holds**, scoped by the Gist that person is handed. An MCP server without its key simply doesn't connect.

```bash
# macOS/Linux — install or update, then health-check
cd ~/kun && bash .claude/scripts/setup.sh engineer

# Windows (PowerShell)
cd ~/kun; .\.claude\scripts\setup.ps1 -Role engineer
```

Re-run anytime after pulling from git. Fresh machine? Start at [Onboarding](/docs/onboarding) — one paste does everything.

## Config Health

Every member's config is verified continuously and reported to a shared GitHub issue.

```bash
bash ~/.claude/scripts/health.sh            # local check
bash ~/.claude/scripts/health.sh --report   # check + report to GitHub

.\.claude\scripts\health.ps1                # Windows
.\.claude\scripts\health.ps1 -Report
```

Or say `health` inside Claude Code:

| Phrase | Result |
|:-------|:-------|
| `health` | Local check + team dashboard from GitHub |
| `health report` | Post local health to GitHub |
| `health all` | Every member's latest status |

Checks: core files exist, JSON valid, engine counts match `engine.json`, permissions correct, CLI + agent fleet installed, config staleness.
