# Machine

> The desktop app for people who do not live in a terminal. It wraps the same Claude Code the engine uses, shows the skills and agents of **their department**, and keeps everything on their own computer.

Machine is a small Rust + Tauri 2 app that lives in its own repo, [databayt/machine](https://github.com/databayt/machine) (moved out of kun on 2026-11-17). The window shows a bundled static export of the UI (local-only IPC, no remote origin); every feature's Rust lives beside its UI in `src/components/<feature>/rust.rs`. It talks to kun.databayt.org (`/api/machine/*`, served by this repo) and GitHub. Development instructions (build, test, CI) are in that repo's README. It never proxies a model: it starts the unmodified `claude` binary, signed in with the teammate's own account.

## Install on Windows 11

Needs Windows 11, an internet connection and GitHub access to `databayt/kun`. Open **PowerShell** and run (one line):

```powershell
irm https://raw.githubusercontent.com/databayt/kun/main/.claude/scripts/setup.ps1 -OutFile $env:TEMP\kun-setup.ps1; powershell -ExecutionPolicy Bypass -File $env:TEMP\kun-setup.ps1 -Machine moed
```

If the repo is private, or the installer is a file you were handed, clone first (Git opens a browser sign-in) and run from the clone:

```powershell
cd $env:USERPROFILE\kun; powershell -ExecutionPolicy Bypass -File .\.claude\scripts\setup.ps1 -Machine moed -MsiPath $env:USERPROFILE\Downloads\Kun.msi
```

`-Machine <login>` is the **only** thing the script does for a machine login. It is safe to re-run: every step checks first.

| Step | What happens |
| --- | --- |
| Windows 11 | Checks the build; warns on anything older |
| Git | Installs it with `winget` if missing |
| WebView2 | Checked; Windows 11 ships it, and the installer downloads it if not |
| Claude Code | Installed with the official installer (`irm https://claude.ai/install.ps1 \| iex`) |
| kun | Cloned to `%USERPROFILE%\kun` (machine reads `machines\` and `departments\` from it) |
| Settings | Writes `%USERPROFILE%\.kun\machine\settings.json` from `machines\<login>.json` |
| Machine | Installs the `.msi` you pass with `-MsiPath` or `-MsiUrl`, else the latest release of `databayt/machine` |

It does **not** run the engine install: no hooks, no rules, no full skill set. The app's catalog installs the items of the person's profile.

With no `-MsiPath` or `-MsiUrl`, the script downloads the `.msi` of the [latest release of databayt/machine](https://github.com/databayt/machine/releases/latest); a build artifact of that repo's CI also works (pass it with `-MsiPath`). The installer is unsigned. Because it is unsigned, Windows SmartScreen shows **More info → Run anyway** once on first launch.

## First run

1. In PowerShell run `claude` once and sign in with **your own** Claude account. Nobody signs in for you.
2. Open **Kun** from the Start menu. The app picks up your name, department and agent from `settings.json`.
3. The app opens on **Install** until the computer is ready. Press **Install everything**, sign in where it asks, then open **.claude → departments** and install your department's pack. After that, ask in Arabic or English.
4. Voice (optional): press the microphone, and the app downloads a small speech model once (about 142 MB). It runs on the CPU and nothing leaves the computer. A larger, slower, more accurate model (`small`, about 465 MB) can be chosen instead. Spoken replies use the Windows voices.

## The sidebar

The sidebar is the whole navigation. There is no title, toolbar or tab row in the work area: a screen shows content only. Click a link and its sub-links open under it; click one of those and the screen swaps to it. The lines under the open link are your path, so the sidebar is also the way back: click any line above to go up a level. On a narrow window the same four links are in the menu.

| Link | Open it when | What is under it |
| --- | --- | --- |
| **Sessions** | You want a chat you had before | Every past chat on this computer: reopen, rename, delete |
| **Install** | The computer is new, something stopped working, or you want something removed | The seven stages of a ready computer, each with its count (`9/11`), then each stage's steps |
| **.claude** | You want to see, add, remove or switch off what the agent can do | The folders of `~/.claude`: `skills`, `agents`, `rules`, `hooks`, `departments`, `mcp` |
| **Settings** | You are changing how the app or the engine behaves | General, Config, Health, Engine |
| Docs | You want to read how something works | Opens these pages in the browser |
| Mathematics | You want the curriculum walk-through | Starts a chat about it |

The number beside **Install** (`· 82%`) is how ready the computer is; it disappears at 100%.

**Settings, link by link**

- **General**: language, who you are and your department. (The default agent is under **Install → Agents → Default agent**; every repo is under **Install → Repos → All repositories**.)
- **Config**: the notifications line, your personal `settings.json` keys and the team secrets file. Every change is backed up first, and a failed health check puts the old content back.
- **Health**: the engine's health check and app updates.
- **Engine**: the engine's version and its own update. Hidden on machines whose profile does not manage the engine.

## Install and uninstall

Install is the wizard. It follows the same catalog the one-liner uses (`.claude/machine/readiness.json`), so the app and the terminal never disagree about what "ready" means.

| Stage | What it covers |
| --- | --- |
| Identity | GitHub CLI, GitHub sign-in, membership of the databayt organization, SSH key, git name and email |
| Accounts | Claude sign-in, Slack, team secrets, CRM keys, and for engineers Cloudflare, Vercel, AWS and Neon |
| Foundation | Homebrew, git, Node 24, pnpm, jq, uv, ffmpeg, tesseract, tmux, Chrome, Colima |
| Repos | The repos folder, the kun, hogwarts and codebase clones, each product's `.env` |
| Agents | Claude Code and Desktop, Antigravity, opencode, Codex, Hermes |
| Engine | The engine's config in `~/.claude`, its MCP servers, the daily heartbeat, the devices lane |
| Tools | Your department's apps: WebStorm and VS Code for tech; Blender, FilmCraft, OBS and ComfyUI for video |

How to use it:

1. Open **Install**. The first screen shows how ready the computer is and one button, **Install everything**. It runs every step that needs no person.
2. Steps that need you are marked. Each has one button that takes you to the right place: **Sign in** opens Terminal with the command, **Open** opens the page (for example the organization invite), **Ask Abdout** sends him the request.
3. Open a stage to see its steps, or one step to see the exact command it runs and what it waits for.
4. **Heal with agent** hands whatever is still failing to Claude, in the kun folder, with the `provision` skill.

**Uninstall** is on every step the wizard installed. Before it removes anything the app shows what still depends on the step, and it refuses while something installed needs it.

- Apps and command-line tools are removed with the same tool that installed them.
- Repos and `.env` files go to the **Trash**, not deleted. A repo with uncommitted, stashed or unpushed work is refused.
- Sign-ins are signed out in Terminal.
- **Homebrew, Node, the kun repo and Claude Code are keystones**: the app itself stands on them. The app never removes them by itself. It opens Terminal with the command and tells you that Machine cannot install anything afterwards; the [one-liner](/docs/onboarding#the-one-liner) brings it all back.
- Steps with nothing on the computer to remove (organization membership, Slack, CRM keys) have no Uninstall.

What you remove stays removed. The step shows as **removed by you**, it no longer counts against the percentage, and the daily heartbeat does not put it back. Press **Install** on it to bring it back.

## The `.claude` control room

**.claude** shows the agent's config folder the way Finder shows a folder: folders and files, nothing else.

| Folder | What is in it | What you can do |
| --- | --- | --- |
| `skills` | What the agent knows how to do (`draft`, `deploy`, `funnel`, …) | Install, uninstall, switch on or off |
| `agents` | The specialists it can hand work to | Install, uninstall, switch on or off |
| `rules` | Standing instructions it always follows | Install, uninstall, switch on or off |
| `hooks` | Scripts that run on events | Install, uninstall |
| `departments` | A department's pack: its skills and agents in one item | Install the pack, or open it and pick items |
| `mcp` | The outside services the agent can reach | Switch a server on or off |

The first screen also shows three files, `CLAUDE.md`, `settings.json` and `.env`; opening one takes you to **Settings → Config**, where they are edited. Each folder ends with one line, for example `86 items · 61 on`.

How to read a folder:

- A normal icon is **installed** and on.
- A dimmed icon with a download mark is **available** from kun but not on this computer. Open it and press **Install**.
- A greyed icon is **switched off**: the file is kept aside, and the agent no longer sees it. The switch under the icon brings it back exactly as it was.
- A blue dot means kun has a newer version: open it and press **Update**.
- An icon with a person mark is **yours**: something you made. The app can switch it off, and it never deletes it.

The difference between the two verbs: **switch off** keeps your copy and is undone with one click; **uninstall** removes kun's files. Both survive the daily engine refresh, which otherwise copies every engine item back.

Hooks have no switch on purpose. A hook is wired from `settings.json`, and a missing file would raise an error on every event; install or uninstall it instead.

## What Moed's machine can and cannot do

Profile: `machines/moed.json` — departments **sales**, **marketing**, **video**; agent **Claude**.

**Can**

- Sales: proposals, pricing, scrape and funnel once the Twenty key is set.
- Marketing: draft, calendar, social, carousel, measure and approve. Publishing stays behind kun's approve queue.
- Read the kun, hogwarts and mkan repos; write only in his own workspace.
- Talk to the agent in Arabic or English, by text or voice, and hear replies.

**Cannot**

- Change code in the repos (read-only) or touch the engine (hidden for this login).
- Use the video lanes (edit, shoot, record, higgs) until each is ported: they still have macOS-only steps and are marked Mac-only in his menu.
- Publish anything on a brand page without a human approval.
- Run the engine's hooks or its Mac-only scripts.

## Tasks and the gate

Work reaches the app as GitHub issues. The captain and weekly skills draft them; nothing is created until Abdout says "send". Each task carries a `dept:<department>` label, the sprint as its milestone (`Sprint <yyyy>-W<ww>`), a `P0` to `P3` priority and a hidden kun block naming the repos and catalog items it needs and the tasks it waits for (`after`).

What a person sees in their department:

- **The queue**, ordered by sprint, then priority, then what it waits for, then age.
- **Readiness** on the top task: the repos it needs are local and fresh, its catalog items are installed, your profile allows them, every task it waits for is closed, and nobody else holds it. Anything missing is listed with a one-tap fix (clone the repo, install the items).
- **Start**, once ready. It claims the task (it shows as in progress, with a comment saying which machine) and opens a chat seeded with the issue, its kun block and the repos.
- **One task at a time.** Start is refused while you hold another in-progress task, unless the CEO has granted `wip:2`. Release hands a task back.
- **Done** moves it to review with a summary comment. It is not finished yet.
- **The CEO closes it.** Only a closed issue counts as done, so nothing is skipped silently, and tasks waiting on it become ready.

Holder and status labels are managed by the machines, never set by hand.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| "running scripts is disabled" | Run it through `powershell -ExecutionPolicy Bypass -File ...` as shown above |
| Clone fails | Sign in to GitHub in the browser prompt Git opens, then re-run |
| `claude` not found after install | Open a new PowerShell window |
| Voice is slow | Keep the default `base` model; do not switch to `small` on a laptop without a GPU |
