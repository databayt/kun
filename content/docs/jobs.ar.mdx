# محرك الوظائف (Job Engine)

> **"الأدلة فوق الكلمات المفتاحية. القدرات فوق المسميات الوظيفية. التفسير المشروح فوق الأرقام المبهمة."**

**محرك الوظائف (Job Engine)** هو منصة العمليات المهنية داخل Kun. بدلاً من بناء محرك بحث ساذج يقوم بمطابقة سطحية لكلمة "React" دون فهم عمق المهارة، يقوم هذا النظام بفحص الكود المصدري الحقيقي لمستودعات ومشاريع **Databayt**، وبناء **ملف معرفة هندسي (Engineering Knowledge Profile)** موثق بالأدلة، وتطبيع عروض العمل في السوق، وتقييم مدى التوافق بنموذج خماسي الأبعاد قابل للشرح بالكامل.

---

## 1. الفلسفة الأساسية

تفشل محركات التوظيف التقليدية بطريقتين متماثلتين:
1. **وهم الكلمات المفتاحية**: مطور كتب 10 أسطر تمهيدية في لغة ما يُعامل بنفس درجة مطور بنى بروتوكولات موزعة وأنظمة إنتاجية كاملة.
2. **جمود المسميات الوظيفية**: شخص بنى وأنظمة SaaS متعددة المستأجرين من الصفر (مثل Hogwarts) يُصنف كغير مؤهل لوظائف "Full-Stack AI Engineer" أو "Founding Engineer" لمجرد أن مسمّاه السابق لم يتضمن الكلمة الرنانة بالحرف.

يحل محرك Kun هذا التحدي عبر **الإسناد القائم على الأدلة الحقيقية**:

| المبدأ | الأسلوب التقليدي | محرك الوظائف في Kun |
| :--- | :--- | :--- |
| **أساس التقييم** | كلمات مفتاحية يدعيها الشخص في سيرته | فحص حقيقي لمستودعات github.com/databayt ونماذج Prisma و Server Actions |
| **المطابقة** | نسبة تطابق النصوص | تقييم خماسي الأبعاد + مطابقة المشكلات وحلول Databayt السابقة |
| **ملاءمة البناء** | افتراض التخصص الضيق فقط | تقييم قدرات البناء من الصفر (0-to-1) والملكية الشاملة للمنتج |
| **المخرجات** | نسبة مئوية غامضة | تقرير مشروح يربط كل شرط وظيفي بملفات وشواهد الكود مع نقاط للمقابلة |
| **التموضع** | تضخيم المسميات | تموضع صادق وقوي (من هندسة الكهرباء إلى بناء البرمجيات) |
| **الإجراء** | حفظ الروابط في مكان معزول | تصدير بضغطة زر واحدة إلى Twenty CRM (`sales.databayt.org`) |

## 2. قاعدة أدلة مستودعات Databayt (github.com/databayt)

يقوم المحرك بفحص الكود عبر القارئ العميق لمستودعات **`github.com/databayt`** مع تسريع محلي لـ AST:

```
1. معمارية SaaS متعددة المستأجرين (Multi-Tenant):
   - hogwarts/prisma/schema.prisma → أكثر من 30 نموذجاً علائقياً مع عزل تام بـ schoolId
   - hogwarts/src/auth.ts → مصادقة NextAuth v5 مع حماية الصلاحيات المبنية على الأدوار
   - hogwarts/src/lib/whatsapp/ → خط إنتاج رسائل WhatsApp المؤتمتة عبر Evolution API
   - hogwarts/scripts/crm/twenty-rest.ts → عميل Twenty CRM REST الموثوق

2. أنظمة التصميم والحرفية في الواجهات (Design Systems):
   - codebase/src/components/ → 54 مكوناً أولياً و 62 مكوناً ذرياً و 31 قالباً
   - apple/src/app/ → استنساخ بكسل-بدقة لتصميم Apple في Next.js 16 و React 19
   - mkan/src/components/search/ → محرك حجز وتقويم تفاعلي وفلاتر بحث جغرافية

3. تكامل الذكاء الاصطناعي والأتمتة (AI Engineering):
   - kun/src/lib/google-draft.ts → توليد مخرجات مهيكلة بمخططات Zod مع Gemini 2.5
   - kun/.claude/agents/ → أسطول من 28 وكيلاً ذكياً مع ذاكرة دائمة وحواجز حماية
   - kun/scripts/crawl-anthropic/ → زاحف آلي وتوثيق هيكلي للأصول

4. الأنظمة وتطبيقات الهاتف الأصلية (Mobile & Systems):
   - distributed-computer/crates/ → برمجيات Rust متعددة الحزم، شبكات libp2p، وجداول Kademlia DHT
   - ios-app/Sources/ → تطبيق iOS أصلي بلغة Swift 6 و SwiftUI 18 مع مزامنة دون إنترنت
   - android-app/app/ → تطبيق أندرويد أصلي بلغة Kotlin و Jetpack Compose
```

## 3. خوارزمية المطابقة خماسية الأبعاد (5D Matching)

تُحسب درجة التوافق وفق المعادلة التالية:

```text
الدرجة الإجمالية = 0.40 * التقني + 0.30 * القدرات + 0.15 * النطاق + 0.15 * واقعية المنصب - عقوبة الفجوات الحرجة
```

### مستويات التوصية

- **أولوية قصوى (High Priority)** (85%+ وبلا فجوات مانعة): تطابق تام مع قدرات البناء الفعلية المثبتة.
- **توافق قوي (Strong Fit)** (70% - 84%): أساس هندسي قوي وفجوات ثانوية سهلة التعلم.
- **تجهيز وتقديم (Prepare & Apply)** (55% - 69%): توافق جيد يتطلب تحضيراً لبعض جوانب المقابلة.
- **احتمالية منخفضة (Low Probability)** (أقل من 55% أو فجوتان حرجتان فأكثر): عدم توافق في التقنية أو النطاق الجوهري.

## 4. التكامل مع Twenty CRM

يتم ربط الفرص المؤهلة تلقائياً بمساحة العمل **`databayt`** على الرابط **[`sales.databayt.org`](https://sales.databayt.org)** عبر عميل REST المخصص:

- عنوان الفرصة: `[اسم المنصب] @ [الشركة]`
- المرحلة: `QUALIFIED` أو `HIGH_PRIORITY`
- الملاحظات: الدرجة الكاملة، ملخص التقييم، أقوى الأدلة من المستودعات، ونقاط الحديث في المقابلة.

## 5. تشغيل واختبار المحرك

```bash
# فحص الأنواع TypeScript
pnpm typecheck

# تشغيل اختبارات الوحدة والتكامل
pnpm test src/lib/jobs/__tests__/job-engine.test.ts

# مزامنة قاعدة البيانات
npx prisma db push
```

### صفحات الواجهة

- **`/jobs`**: لوحة التحكم التفاعلية للوظائف، إدخال الفرص، الفلترة، وبطاقات التقييم المشروحة.
- **`/jobs/profile`**: ملف الأدلة الهندسية الشامل والقدرات المثبتة.
