# PWA

The engine's lane for Progressive Web Apps. Say it in prose — _"make balqalam installable"_,
_"attendance should work offline"_, _"push notifications for parents"_ — and the `/pwa` runbook
activates with the `pwa` agent, the `pwa` pattern card, and the audit script.

**The phone is the client and there is no native app budget.** Teachers mark attendance on
phones, parents read absences on phones, hosts answer guests on phones. A PWA gives them a
home-screen icon, an offline shell and browser push with no app store, no Swift or Kotlin build,
and no per-platform cost. Cash flow first: the paying pilot runs on the web app, so the web app
has to earn the home screen.

| Product  | Verdict   | Why                                                                                                                                                                                                                              |
| -------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| hogwarts | **yes**   | Daily field flows on phones (quick attendance, kiosk, parent portal). A PWA layer already shipped and was half-broken. The notification model already carries the push columns and a cron.                                       |
| mkan     | **defer** | Guests are one-visit and contact-only — the only volume event is a phone call. Hosts have no real message volume yet. Reopen when host messaging moves; fix the canonical host, `themeColor` and dictionary every string first. |

Framed under Lean Startup (canon #13/#15) as a hypothesis with a metric: an installed app and
offline attendance raise the share of daily attendance submitted from phones. Measured by the
outbox `applied` rate and attendance rows per week; reviewed after four weeks.

### What was actually broken

Verified live on `demo.balqalam.com` and `kingfahd.balqalam.com` before any code changed:

- Five icons the manifest and worker named returned **500** — shortcut icons, push icons, the
  iOS home-screen icon.
- The manifest was static, English and single-tenant on an Arabic-default multi-tenant product.
- The worker precached `/` and `/offline`, both **307**s to the locale prefix. A redirected
  response is refused for navigations, so the offline fallback never worked — silently.
- Every navigation and every `/api/` GET was cached with no user key: a shared school device
  could replay the previous user's dashboard.
- The push handler hardcoded a product name, dead icons, and a click that always opened `/`.

## The pattern

The full layout is the `pwa` pattern card. The load-bearing choices:

- **The manifest resolves its own tenant.** Middleware matchers exclude dotted paths, so
  `/manifest.webmanifest` never sees the tenant headers. The route reads the host, resolves the
  school, and answers with its name, language, direction and colour. `start_url` stays relative.
- **Hand-rolled worker on large apps.** A 30 MB app's whole-bundle precache is hostile to Sudan
  and UAE mobile data. The worker precaches only the locale offline pages, caches hashed static
  assets lazily with a cap, and treats navigations and `/api/` as network-only. Serwist is the
  answer for a small greenfield app.
- **Outbox, not cache, for offline writes.** IndexedDB holds the pending work; the sync route
  applies each kind idempotently and answers `applied`, `duplicate` or `rejected`.
- **Push on the existing rails.** Web Push adds a subscription store and a processor; the FCM
  scaffold stays a no-op until a native app wants it.
- **iOS order.** No install prompt event; Web Push reaches installed apps only — install first,
  push second.

One domain rule guards the worker: `next-16/sw-no-authenticated-cache` auto-loads whenever a
service worker file is touched.

## What shipped on hogwarts (2026-09-12)

Four phases, four commits on `main`, one deploy to `balqalam.com` (Worker `7e2f5791`, since
superseded by the rotation and bridge deploys):

| Phase | What a school gets                                                                                                                                                                                                                              |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1     | An installable app named after the school, Arabic and right-to-left by default, in the school's colour; real icons; a service worker that keeps only public assets and shows the locale's offline page when the connection drops               |
| 2     | Quick attendance that survives a dropped connection: marks queue on the phone and replay through the same ownership check as the online path; a newer mark on the server wins                                                                     |
| 3     | Web Push on the existing notification rails: a device subscribes from the preferences page; absence, exam and live-class notices arrive as system notifications and deep-link into the school's app; iPhone only from the installed app          |
| 4     | An install card on phone-sized dashboards — the real install prompt on Android, the Share → Add to Home Screen hint on iPhone                                                                                                                    |

## How to experience it

On any school host today (`demo.balqalam.com`, `kingfahd.balqalam.com`):

1. **Install** — sign in on a phone, tap **Install** on the card at the top of the dashboard
   (Android) or Share → *Add to Home Screen* (iPhone). The home-screen icon opens the school
   full-screen with its own name and colour.
2. **Mark attendance offline** — *Attendance → Quick*, airplane mode on, mark a section, save;
   the sync banner shows one pending item. Network back on → it drains within seconds and the
   marks are on the server. Save again and the newer mark wins.
3. **Turn on push** — *Notifications → Preferences → Push*, allow the permission. Have a teacher
   mark a child absent: on the next cron tick (every 15 minutes) the guardian's phone shows the
   absence and a tap opens it in the app.
4. **Lose the connection anywhere** — airplane mode, open any route: the school's offline page in
   the right language, with the outbox listing what is queued.

The user-facing walkthrough lives in the product docs: hogwarts *Offline*, *Attendance* and
*Notifications* pages, in English and Arabic.

### Verified, and owed

Verified by tooling on production: the install audit passes on both hosts (0 FAIL), the worker
controls the page after one reload with both locale offline pages precached, the outbox replay
answers `applied` then `duplicate`, and the push cron reports the channel configured. Owed to a
human with a phone, because no tooling can grant the notification permission or cut the network
under the service worker: a push actually showing on a device, and the offline page under a real
disconnect — tracked in hogwarts#408. Lean Startup review date: 2026-10-10 (outbox `applied` rate,
attendance rows per week).

## Verification

1. Audit → 0 FAIL: Arabic `name`, `dir: rtl`, every icon 200, no redirecting precache entry.
2. Browser: the worker controls the page after one reload; offline emulation renders the
   locale-correct offline page.
3. Outbox: a write made offline drains on reconnect and replays as `duplicate`.
4. Push: subscribe, queue one notification, hit the cron — it lands and its tap deep-links to
   the tenant route.
