# Token harvest

> Claude on the Max plan does the judging. Everything easy runs on free tokens, and when one free
> source runs dry the next one takes over — without anyone noticing.

Each person's Mac runs one **token pool**: [OmniRoute](https://github.com/cheaper-inference/OmniRoute)
(MIT) on `127.0.0.1:20128`, holding that person's own free accounts. kun decides which sources exist
and how they rank; the Kun app installs it, takes the keys and shows its health.

## Use it

### In the terminal

| You type | You get |
| --- | --- |
| `c` | Claude Code on your Claude plan — the judge, the real work |
| `f` | Claude Code on free models — the pool when it is ready, Nous direct when not |
| `f --pool kun-long` | `f` on a named class (`kun-code`, `kun-fast`, `kun-long`, `kun-vision`) |
| `f --direct` | `f` straight to Nous, skipping the pool |
| `o` | opencode on OpenCode Zen's free models (no key) |
| `o -m omniroute/kun-code` | opencode on the pool |
| `h` | Hermes (chat gateway) on Nous free models |
| `a` | Antigravity on your Google account |
| `lane o "explain this repo"` | one prompt through any agent, answer printed, no session |
| `lane pool` | every source: connected, dry, missing key, requests, tokens |
| `lane test` · `lane --pool test` | the same bug-fix task through every agent — PASS/FAIL + seconds |
| `lane models` | which model each agent is set to |

Rule of thumb: **easy, public, mechanical → `f` or `o`. Anything with client data, secrets, or
judgment → `c`.** Free providers can read what you send.

### In the Kun app

| Where | What |
| --- | --- |
| **Terminal** (sidebar) | pick `c a o h f`, it opens in a tab; several tabs at once |
| **Settings → Model** | choose who runs Claude Code in the app: Claude, NVIDIA, OpenRouter or OmniRoute (the pool) |
| **Settings → Model → OmniRoute → Providers** | every source in the catalog: status, use, quota. Tap one → **Get key** → paste → **Save and connect** → **Test** |
| **Settings → Model → OmniRoute → Set up pool** | installs and wires the pool in one go (shown when it is not ready) |
| **Settings → Health** | a *Token pool* line: green ready, yellow a source dry or keys missing, red the gateway down |
| **Settings → Agents** | the `c a o h f` commands in your shell |
| **Setup** (sidebar) | readiness steps, including the pool's: gateway, ready, ledger job, keys |

When Claude hits its limit in an app chat, the run moves to the pool by itself (if the pool is
ready) and the model chip says *fallback*.

### Add a free source (two minutes each)

Settings → Model → OmniRoute → Providers → the source → **Get key** opens its page:

| Source | Where the key is | Note |
| --- | --- | --- |
| NVIDIA | build.nvidia.com → API keys | Nemotron 3 Ultra 550B, ~40 req/min |
| OpenRouter | openrouter.ai → Keys | set an expiry and a credit limit of 0 |
| Google AI Studio | aistudio.google.com → Get API key | Gemini Flash |
| Groq | console.groq.com → API Keys | fastest |
| Mistral | console.mistral.ai → API keys | pick the free *Experiment* plan |

Paste → **Save and connect**. The key goes to this Mac's credential store only; the pool re-ranks
at once. Three or more connected sources turns the *Free model keys connected* step green.

## The three ways, all used

From [sharbel.com — Claude Code on a free 550B model](https://sharbel.com/articles/claude-code-free-550b-model) (2026-11-08):

| Way | What | Where it lives here |
| --- | --- | --- |
| 1 · Free Claude Code + NVIDIA | Nemotron 3 Ultra 550B, ~40 req/min, free key at build.nvidia.com | NVIDIA is a pool provider; Machine → Brain also offers the NVIDIA route through `fcc-server` |
| 2 · OpenRouter `:free` | 50 req/day, 1,000/day after a one-time $10 top-up | A pool provider; the top-up is an approved paid rung, off until funded |
| 3 · OmniRoute | One endpoint over 150+ free providers, falls over when one runs out | The pool itself |

## The catalog — `.claude/machine/providers.json`

One row per source: tier, sign-up link, the credential-store name of its key, published limits,
privacy class, and the best models for each **role** (`coding`, `fast`, `vision`, `long`).

| Tier | Meaning | Today |
| --- | --- | --- |
| keyless | no account | OpenCode Zen (inside opencode only) |
| free | account, no card | Nous (via Hermes), NVIDIA, Google AI Studio, Groq, Mistral, Antigravity |
| free-capped | free with a hard cap | OpenRouter, Cloudflare Workers AI |
| paid | money; off until funded + `/decide` | OpenRouter $10 top-up, DeepSeek (weekly cap), Cerebras |
| plan | a subscription — **never pooled** | Claude Max (only in native Claude Code) |

**Per person.** Free-tier terms bind the account holder, so every key is the teammate's own and
lives only in their credential store (service `org.databayt.kun.machine`, the same items Machine →
Brain writes). Free providers may read prompts: client data and secrets stay on Claude.

## The classes — OmniRoute combos

`scripts/harvest/combos.mjs` builds one combo per class from the connected providers' roles, in
catalog order (the catalog order *is* the ranking). Strategy `priority`: the first healthy model
serves; when it is exhausted, rate-limited or failing, OmniRoute moves to the next.

| Combo | Role | Used by |
| --- | --- | --- |
| `kun-code` | coding | `f` (default), `o -m omniroute/kun-code` |
| `kun-fast` | fast | `f`'s haiku and subagents |
| `kun-long` | long context | `f --pool kun-long` |
| `kun-vision` | images | `f --pool kun-vision` |
| `kun-thrifty` | coding, then paid rungs | only when a paid rung is on |

## The agents on it

| Launcher | Runs on |
| --- | --- |
| `c` | Claude Max — native, never pooled |
| `f` | the pool (`kun-code`) when the ledger says ready, else Nous direct; `f --direct`, `f --pool <combo>` |
| `o` | OpenCode Zen keyless by default; the pool with `-m omniroute/kun-code` |
| `h` | Hermes on Nous longcat-2.5 → hy4-flash → solar-mini4 |
| `a` | Antigravity (Google account) |
| `d` | DeepSeek, own key |

Scripted: `lane <c|a|o|h|f|d> "prompt"`, `lane --pool [combo] <f|o> "prompt"`, `lane test`,
`lane --pool test`, `lane pool` (the ledger table), `lane models`.

## The ledger — what is left, what is dry

`scripts/harvest/harvest.mjs` runs every 30 minutes (launchd `com.databayt.harvest`, through
`job-run.sh`, job `harvest`) and writes `~/.claude/state/harvest.json`: per source its status
(`connected`, `needs-key`, `exhausted`, …), requests, tokens, success rate and quota when the
provider reports one. It also pushes Hermes's one-hour Nous key into the pool and unlocks
connections a dead model locked. Read by `aware.md` (Token pool line + alert), `health.sh`
(token pool check), `f` (pool or direct) and Machine (Brain → Providers, health).

## Setup — Machine drives it

Readiness steps (`.claude/machine/readiness.json`, stage *agents*), each with an automatic fix:

1. `omniroute.cli` — `npm install -g … omniroute@3.8.54`
2. `omniroute.service` — `scripts/harvest/omniroute.sh install`: launchd, loopback only, an API key
   required, a random admin password (the shipped one is the public `CHANGEME`)
3. `pool.ready` — `omni.mjs setup`: mint the client key, connect every source that has a key, build
   the combos
4. `pool.job` — `job.sh --install`
5. `pool.keys` — **the human step**: Machine → Brain → Providers → *Get key* on each free source,
   paste, done (≥ 3 connected turns it green)

## Lessons (2026-11-24)

- OmniRoute assumes a **32,768-token** window for any model its catalog lacks, and Claude Code's
  prompt alone is ~34k — so such models were skipped. `providers.json` `context` carries the real
  window; `omni.mjs` writes it into OmniRoute's `model_context_overrides` table.
- A 410 on **one** model (Cloudflare retired `kimi-k2.6` on 2026-11-20) locks the **whole**
  connection for 24 h. Keep dead models out of `roles`; `harvest.mjs` unlocks and names the model.
- OmniRoute's `auto/*` models also route to keyless providers it pre-registers (some reverse-engineered).
  kun clients never ask for `auto` — only `kun-*` combos over sources the person connected.
- `opencode run` reads a non-tty stdin as prompt and waits forever: scripts close stdin.
- Nous's Anthropic endpoint wants `Authorization: Bearer`, not `x-api-key`.

## Test it yourself

Fifteen minutes, in order. Each step says what you should see.

**Terminal**

1. `lane pool` — `gateway ok · pool ready`, and `connected` next to nous and cloudflare.
2. `lane test` — c, o, h, f say `PASS` (a says `FAIL … not eligible` until you verify Antigravity).
3. `lane --pool test` — f and o say `PASS` through the pool.
4. `f --print-env | head -3` — `ANTHROPIC_BASE_URL=http://127.0.0.1:20128` and `kun-code`.
5. `f` — ask *"make a file hello.txt that says hi"*; it does it. Quit with `/exit`.
6. `lane o "reply with OK"` — `OK`.
7. `bash ~/kun/.claude/scripts/health.sh | grep "token pool"` — ✅.

**Kun app** (quit and reopen it after an update)

8. **Terminal** → pick **f** → type `say hi` → an answer in the tab. Open a second tab with **o**.
9. **Settings → Model** → the OmniRoute card shows ready with model `kun-code`.
10. **Providers** → nous and cloudflare *connected*; nvidia, openrouter, gemini, groq, mistral
    *needs key*; DeepSeek and the OpenRouter top-up *approved, off until funded*; Claude Max
    *never in the pool*.
11. Tap **NVIDIA** → **Get key** → your browser opens build.nvidia.com → make a key → paste →
    **Save and connect** → *connected* → **Test** → ok with a latency. Repeat for the others.
12. `lane pool` in a terminal — the source you added is now `connected`.
13. **Settings → Health** — *Token pool* green.
14. **Setup** — the pool steps are ticked; *Free model keys connected* turns green at three sources.

**The swap** (optional)

15. In **Providers**, note which source is first in `kun-code`. In a terminal:
    `node ~/kun/.claude/scripts/harvest/omni.mjs list` → copy its connection id →
    disable it in the OmniRoute dashboard (`omniroute dashboard`, password:
    `bash ~/kun/.claude/scripts/harvest/omniroute.sh admin`) → `lane --pool test f` still
    `PASS`, served by the next source. Re-enable it.

If a step fails, `tail ~/Library/Logs/omniroute.log` and `cat ~/.claude/logs/harvest.out` say why.
