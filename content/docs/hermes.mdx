**Hermes** ([hermes-agent](https://github.com/nousresearch/hermes-agent) · [site](https://hermes-agent.nousresearch.com) · MIT) is the engine's optional **assistant gateway** — the `h` lane. It is NOT a coding CLI: it bridges chat apps (Slack, WhatsApp, Telegram, Discord, Signal, Email, …) to an agent running on your machine, so you can reach the engine from wherever the conversation already is. **Slack is databayt's wired channel; WhatsApp (Abdout's personal number) is wired for the jobs lane since 2026-10-05.** Since 2026-11-01 Hermes is the **ears** and Claude Code the **hands**: real work asked for in Slack is handed to Claude Code (Opus 5.5) on the Mac through the [bridge](#claude-code-bridge).

Hermes replaced OpenClaw as the gateway lane. If a machine previously ran OpenClaw, Hermes imports its persona, memories, skills, and platform configs in one command:

```bash
hermes claw migrate --dry-run   # preview
hermes claw migrate             # import from OpenClaw
```

## Install

The onboarding wizard installs Hermes when the **Hermes (gateway)** lane is selected (default: all lanes). Manually:

```bash
# macOS / Linux / WSL2
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

```powershell
# Windows (PowerShell)
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

Installs to `~/.hermes` (Windows: `%LOCALAPPDATA%\hermes`), CLI binary `hermes`, launcher alias `h` (written into the managed `# BEGIN databayt agents` block). First-time model/provider setup: `hermes setup`.

## Gateway — wire the channels

The gateway is a single background process that runs all configured platform adapters at once. Setup is **interactive by design** — onboarding never runs it headless:

```bash
hermes gateway setup     # interactive wizard — select Slack when prompted
hermes gateway run       # run in foreground (this terminal)
hermes gateway install   # install as a user service (persists across reboots)
hermes gateway start     # start the installed service
hermes gateway status    # is it up?
```

Diagnostics: `hermes doctor`.

## Slack wiring (databayt's channel)

Hermes connects to Slack over **Socket Mode** (WebSocket) — your machine needs no public endpoint.

**1. Create the Slack app from the Hermes manifest:**

```bash
hermes slack manifest --write    # writes ~/.hermes/slack-manifest.json
```

Then at [api.slack.com/apps](https://api.slack.com/apps) → **Create New App** → **From an app manifest** → pick the `databayt-sh` workspace → paste the manifest JSON → create. The manifest carries the required scopes (`chat:write`, `app_mentions:read`, `channels:history`, `groups:history`, `im:*`, `files:*`, …) — without `channels:history` the bot cannot see channel messages.

**2. Collect both tokens** and put them in `~/.hermes/.env`:

```bash
SLACK_BOT_TOKEN=xoxb-...     # OAuth & Permissions → Bot User OAuth Token
SLACK_APP_TOKEN=xapp-...     # Basic Information → App-Level Tokens (connections:write)
```

**3. Allowlist yourself** (required — Hermes ignores everyone else):

```bash
SLACK_ALLOWED_USERS=U01ABC2DEF3        # your Slack Member ID (profile → ⋮ → Copy member ID)
```

**4. Optional — proactive notifications.** A home channel lets Hermes *send* (not just reply): scheduled results, background-task completions, broadcasts:

```bash
SLACK_HOME_CHANNEL=C01234567890        # channel details → bottom → Channel ID
```

Invite the bot to any channel it should live in: `/invite @Hermes Agent`. Then:

```bash
hermes gateway setup     # select Slack
hermes gateway install   # persist as a user service
```

> **Hermes-Slack vs Slack-MCP — two different pipes.** The **Slack MCP** (`~/.claude/mcp.json` → `mcp.slack.com`) lets *Claude* post to Slack as a tool (`/slack send …`). The **Hermes gateway** lets *you* talk to an agent on your machine *from* Slack, and lets that agent push proactive notifications back. They coexist; neither replaces the other.

## WhatsApp wiring (personal number, the jobs lane)

Two different WhatsApp pipes exist, and only one fits a person's applications:

| Pipe | What it is | Use |
|---|---|---|
| **Baileys bridge** (`hermes whatsapp`, `WHATSAPP_MODE=self-chat`) | Links Abdout's own WhatsApp as a device, like WhatsApp Web | **Wired.** Job applications to employers and one-line briefs to himself |
| **Cloud API** (`hermes whatsapp-cloud`) | Meta Business API: text only, and outside a 24h window it needs an approved template | Not used. That's why the funnel's school messages are sent by a human |

**Linking.** `hermes whatsapp` refuses to run without a real terminal, so `! hermes whatsapp` in Claude Code fails. Use `pnpm jobs:whatsapp-pair` in kun instead. It runs the same bridge in `--pair-only --pair-json` mode and opens `localhost:8790` with a QR that refreshes itself. On the phone, scan it from the Mac screen: **Settings → Linked devices → Link a device**. A `disconnected (515)` right after the scan means success.

```bash
# ~/.hermes/.env after linking
WHATSAPP_MODE=self-chat
WHATSAPP_ALLOWED_USERS=249919071294   # only Abdout can command the agent; employers' replies are ignored
WHATSAPP_ENABLED=true
launchctl kickstart -k gui/$(id -u)/ai.hermes.gateway   # restart; gateway_state.json → whatsapp "connected"
```

**Sending** works without an LLM, like Slack: `hermes send --to whatsapp:+250788123456 "text"`. An attachment rides as `MEDIA:/path/cv.pdf caption`. The jobs loop sends at most `whatsappCap` (5) cold applications a day. A personal number that messages many strangers gets banned, so the cap stays small.

## Jobs lane commands (no model)

The gateway works the jobs lane through **quick commands**: `type: exec` entries that run a fixed shell command and reply with its output, with no model in the loop. There's no LLM and no arguments, and each must finish in 30s. Type them in your WhatsApp self-chat ("Message yourself") or a Slack DM to the bot:

| Command | Does |
|---|---|
| `/jobs` | Status: last 7 days sent (email · form · WhatsApp), today, queued, held and why |
| `/jobsqueue` | What goes out next. To veto, move the card to Hold on the board |
| `/jobsreplies` | Real replies in the last 14 days (acknowledgements excluded) |
| `/jobspause` · `/jobsresume` | Flip the loop's kill switch (`jobs/.send-off`) |

Install or refresh with `pnpm jobs:hermes` in kun (`scripts/seek/hermes-setup.sh`). It rewrites only the `quick_commands` block of `~/.hermes/config.yaml`, so comments survive and a dated `.bak` is kept. Then it restarts the gateway. Going the other way, the loop pushes a **brief** to the same chat only when an application is accepted: `🎯 Interview` or `🏆 OFFER`. Other replies stay on Slack and the board. Configure it with `briefWhatsApp` in `scripts/seek/config.ts`; `JOBS_BRIEF=off` silences it. The CRM board stays the record. Commands only read it or flip the kill switch.

## Scheduled jobs (cron, no model)

The gateway also runs the engine's local cron jobs. Each one is a script in `~/.hermes/scripts/`, run in **no-agent** mode: the script is the whole job, its stdout goes to the job's channel as written, and empty stdout sends nothing. The gateway must be up for jobs to fire. A daily job missed while the Mac slept still runs if it is less than 2 h late.

| Job | When | Does | Installed by |
|---|---|---|---|
| `mkan-tiktok-sweep` | 06:00 | Kigali TikTok rentals → Twenty homes and TikTok posts → /find leads. The sweep posts its own counts to `#mkan`; Hermes adds a line only when a run fails | `bash scripts/crm/install-tiktok-sweep.sh` (mkan) |
| `mkan-tiktok-post` | 07:00 | Renders the day's TikTok pieces and posts them to @mkan.rw through the session-vault Chrome, which it wakes first | `bash scripts/crm/install-tiktok-post.sh` (mkan) |
| `mkan-tiktok-upload-retry` | 13:00 | Posts whatever 07:00 rendered but could not upload; the day's `uploads.json` keeps it from posting twice | same installer |
| `hogwarts-crm-digest` · `hogwarts-crm-activity` · `hogwarts-snapshot-freshness` | 08:00 · every 2 h · every 3 h | hogwarts CRM digests to a DM | by hand |
| `databayt-daily-social-digest` · `databayt-weekly-social-plan` | weekdays 08:30 · Sun 18:00 | social digest and plan to `#social` | by hand |

The sweep reads for about an hour, longer than Hermes' default 1 h script limit, so its installer sets `cron.script_timeout_seconds: 7200` in `~/.hermes/config.yaml`. Its chat command **`/tiktok`** starts the sweep at once (detached, since `hermes cron run` runs the whole job in its own process and quick commands die at 30 s) and replies with the ledger status. `hermes cron list` shows every job's last result. A job that runs the model (`databayt-4h-heartbeat`) must be **pinned** to it: when the default model changes, Hermes skips every unpinned agent job with "config drifted" rather than spend on a model nobody chose. Pin with `cron.jobs.update_job(id, {"model": …, "provider": "nous"})` from the Hermes venv; the CLI has no flag for it.

## Model — free, never the Claude login

Hermes runs a **free Nous Portal model**: `reflection/beam-1.0-501b-a23b:free` since 2026-11-01 (it answers, uses tools and writes Arabic). `stepfun/step-3.7-flash:free` started refusing every request with HTTP 451 that day. `ornith/ornith-1.5-122b:free` and `upstage/solar-mini4:free` are the tested backups. Today's free list comes from `fetch_nous_recommended_models()["freeRecommendedModels"]` in `hermes_cli/models.py`.

The Nous login expires now and then (`No access token found for Nous Portal login`): run `hermes model`, pick **Nous Portal**, sign in in the browser.

**Never pick the Anthropic provider in Hermes.** Its "API key" option is pay-per-token, which the engine's billing rule forbids. Its "Claude Code" option would run Hermes on the Max subscription login, which Anthropic bans in third-party tools (Feb 2026) and which would put the account at risk. Claude stays where it is allowed: in Claude Code, reached through the bridge below.

## Claude Code bridge

Hermes hands real work to **Claude Code (Opus 5.5)** on the Mac: building, fixing, deploying, kun spells (`social`, `report`, `scrape`, `jobs`…), deep questions about a repo, screenshots to read. `claude -p` is Claude Code itself on the Max plan, so nothing borrows the login.

| Piece | Where |
|---|---|
| The bridge | `kun/scripts/hermes/claude.sh <kun\|mkan>`, task on stdin |
| When to hand off | the Hermes skill `kun` (`kun/scripts/hermes/skills/kun/SKILL.md`) |
| Install the skills | `bash scripts/hermes/install.sh` (kun), then `/new` in the Slack DM |
| Log | `~/.hermes/logs/claude-bridge.log` |

In Slack, just ask ("ask Claude Code in mkan: …", or any build/fix/deploy request). Hermes runs the bridge and stays silent; the bridge posts "on it" and then Claude Code's answer **in the same thread**, as the kun bot, so the free model never reads it. A follow-up in that thread resumes the same Claude session.

Guards: only Abdout's Slack user (`U0AQ0GLDY04`); one run at a time; 15 runs a day (`KUN_BRIDGE_DAILY`); 30 min wall clock. It runs `--permission-mode auto` (Claude Code's classifier approves normal work and blocks risky actions) with permission prompts refused, never `--dangerously-skip-permissions`. Every run draws on the same Max usage as the terminal sessions, which is what the daily cap protects. A trivial run costs about $0.49 of plan usage, mostly from loading kun's context.

## mkan

The `mkan` skill (canonical in the mkan repo, `scripts/crm/hermes/mkan/SKILL.md`, installed by `bash scripts/crm/hermes/install-mkan-skill.sh`) teaches Hermes the /find chat, the WhatsApp line, brokers, the CRM and the TikTok page. It answers with one read-only command, `pnpm -s mkan:read <topic>` (`chats`, `wa`, `crm homes|brokers|consent|tiktok`, `tiktok`). Phones in its output are masked to their last three digits, because it reaches a third-party model. Its one write is `tt:consent`, recording brokers who agreed to TikTok reposts, and only for Abdout. `#mkan` itself stays the intake desk (`home` skill).

## Kun site integration (social egress)

The kun site's Social Hub talks to a Hermes endpoint via env vars (see `.env.example`): `HERMES_API_URL`, `HERMES_API_KEY`, and the client-visible `NEXT_PUBLIC_HERMES_API_URL`. The egress contract is evolving with hermes-agent — the honest boundary stays the same as it was under OpenClaw: **Claude writes the copy; Hermes only relays it**. See [Social](/docs/social).

> **Telegram is not routed through Hermes.** The brand-channel posting lane (`telegram` in the Social Hub) calls the official Bot API directly from the site (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHANNEL_ID`) — a plain HTTPS call that works from Vercel with no local gateway. A future Hermes **Telegram adapter** is the other pipe: chatting with your machine's agent *from* Telegram. Same distinction as Hermes-Slack vs Slack-MCP above.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `h` / `hermes` not found | Restart the shell; the installer adds Hermes to PATH — or re-run the install one-liner |
| Bot doesn't see channel messages | The #1 setup issue is missing **event subscriptions** (`message.channels` / `message.groups`), not just the `channels:history` / `groups:history` scopes — re-create from the manifest (it carries both) and **reinstall the app to the workspace** |
| DMs blocked | Enable the **Messages Tab** in the Slack app's App Home settings |
| Messages silently ignored | Your Member ID isn't in `SLACK_ALLOWED_USERS`, or the channel isn't in `SLACK_ALLOWED_CHANNELS` |
| Scope/event changes not taking effect | Reinstall the app to the workspace (Slack requires it) |
| `'hermes whatsapp' requires an interactive terminal` | Expected from Claude Code. Use `pnpm jobs:whatsapp-pair` (kun) |
| WhatsApp `disconnected 408` during linking | QR expired; the page shows the next one, scan again |
| WhatsApp not in `gateway_state.json` platforms | `WHATSAPP_ENABLED=true` missing, or the gateway wasn't restarted (`launchctl kickstart -k …`) |
| Bridge `node_modules` missing | `npm install` in `~/.hermes/hermes-agent/scripts/whatsapp-bridge` (the pair script does it) |
| Gateway dies on reboot | You ran `hermes gateway run` (foreground) — use `hermes gateway install` for a persistent user service, then `hermes gateway start` |
