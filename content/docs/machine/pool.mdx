# Pool

> Claude on the Max plan does the judging. Everything easy runs on free tokens, and when one free source runs dry the next takes over.

Each person's computer runs one Pool: [OmniRoute](https://github.com/cheaper-inference/OmniRoute) (MIT) on `127.0.0.1:20128`, holding that person's own free accounts. kun decides which sources exist and how they rank; Machine installs the Pool, takes the keys and shows its health.

## Use it

| You type | You get |
| --- | --- |
| `f` | Claude Code on the Pool (class `kun-code`), or Nous direct when the Pool is not ready |
| `f --pool kun-long` | `f` on a named class |
| `f --direct` | `f` straight to Nous, skipping the Pool |
| `o` | opencode on the Pool, class `kun-long` by default (`kun-oc.sh` exports the Keychain key; `/models` picks a Zen model by hand) |
| `o -m omniroute/kun-code` | opencode on a named class |
| `lane pool` | Every source: status, requests, success rate, plus the combos |

## Long sessions

One free source is one daily cap: opencode's keyless DeepSeek stops at "You've used today's free messages". A class is a stack of caps. The first healthy member serves, and when it is exhausted or rate-limited the next one serves under the same session, so the context survives the swap. Every source you connect adds its cap to every class it has a role in, so the horizon grows with each key (NVIDIA, Groq, OpenRouter, Mistral). A Zen API key puts DeepSeek Flash into `kun-long` too.

For a run longer than one sitting, don't count on one session. Keep the plan as a checklist in an issue or a file, commit after each step, and loop short runs that each take the next unchecked step: `f --pool kun-long -p "<step>"` (or a job on the `free` lane), or `o run -m omniroute/kun-long "<step>"` with stdin closed. Claude Max reviews what the free runs produced.

## The sources

`.claude/machine/providers.json` is the catalog: tier, sign-up link, the keychain name of the key, limits, privacy class, best models per role.

| Tier | Meaning | Status today (`lane pool`) |
| --- | --- | --- |
| keyless | no account | OpenCode Zen: `direct-ok` inside opencode only; a Zen API key adds it to the Pool |
| free | account, no card | Nous: connected, 100% ok. NVIDIA, Gemini, Groq, Mistral: `needs-key`. Antigravity: `needs-sign-in` |
| free-capped | free with a hard cap | Cloudflare Workers AI: connected, 90% ok. OpenRouter: `needs-key` |
| paid | off until funded and decided | OpenRouter top-up, DeepSeek, Cerebras: `off` |
| plan | a subscription, **never pooled** | Claude Max: only in native Claude Code |

Settings → Model → OmniRoute → Providers → the source → **Get key** → paste → **Save and connect** → **Test**. The key goes to this computer's credential store only, and the Pool re-ranks at once. Three connected sources turns the *Free model keys connected* step green.

## Privacy

Free-tier terms bind the account holder, so every key is the teammate's own and lives only in their credential store (service `org.databayt.kun.machine`). Free providers may read prompts: **client data and secrets stay on Claude.** The company pays $0; any paid rung is off until funded and recorded with `/decide`.

## Scheduled jobs on the pool

A scheduled job opts in through the `free` lane in `.claude/engine.json`: name it in `jobs.$lanes` (a prefix) or set `jobs.<job>.lane` to `free`. `kun-claude.sh` then runs the job through `kun-free.sh` on combo `kun-long` instead of the Max plan, writes the ledger row with lane `free` and cost 0, and keeps running while the plan is parked. If the free run fails, it retries once on haiku. Same data rule as above: only jobs that touch no client data or secrets belong on it. See [Lanes](/docs/lanes).

## The ledger

`harvest.mjs` runs every 30 minutes (launchd job `harvest`) and writes `~/.claude/state/harvest.json`: per source its status, requests, tokens, success rate and quota. It also feeds Hermes's one-hour Nous key into the Pool and unlocks connections a dead model locked. `lane pool`, `health.sh`, Settings → Health and `f` all read it.

## Setup steps

Readiness steps in the *agents* stage, each with an automatic fix except the last:

| Step | Does |
| --- | --- |
| `omniroute.cli` | installs OmniRoute |
| `omniroute.service` | launchd service, loopback only, API key required, random admin password |
| `pool.ready` | mints the client key, connects every source with a key, builds the combos |
| `pool.job` | installs the 30-minute ledger job |
| `pool.keys` | **you**: add three free keys as above |

## Known traps

- OmniRoute assumes a 32,768-token window for any model its catalog lacks, and Claude Code's prompt alone is about 34k. `providers.json` carries the real `context` window.
- A 410 on one model (Cloudflare retired `kimi-k2.6`) locks the whole connection for 24 hours. Keep dead models out of `roles`; `harvest.mjs` unlocks and names the model.
- Nous's Anthropic endpoint wants `Authorization: Bearer`, not `x-api-key`.
- `opencode run` reads a non-tty stdin as the prompt and waits forever; scripts close stdin.

If a step fails: `tail ~/Library/Logs/omniroute.log` and `cat ~/.claude/logs/harvest.out`.
