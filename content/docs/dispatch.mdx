# Dispatch

One bus for every coding agent on every machine. A task is an issue in `databayt/kun`. A small runner on each machine picks the issues addressed to it, runs the agent headless, and posts the result back on the issue. No server, no queue service: GitHub is the queue.

## The protocol

A task is an issue with these labels.

| Label | Meaning |
| --- | --- |
| `dispatch` | Marks the issue as a bus task (required) |
| `to:<agent>` | `claude`, `codex`, `opencode`, `agy`, `hermes`, `fcc` or `any` |
| `machine:<login>` | Only this machine's GitHub login may run it. Absent means any machine |
| `lane:<name>` | Optional lane (`build`, `research`, `mechanical`, ...) that picks the model |
| `claimed:<host>` | A runner took it |
| `done` / `failed` | Final state |

The body is the brief in markdown, plus an optional fenced `yaml` block:

````md
Fix the failing test in the billing block and push to main.

```yaml
repo: hogwarts        # a folder under ~, ~/oss or ~/Documents, or an absolute path
cwd: /abs/path        # used when repo is absent; default is the kun checkout
timeout_min: 30
model: sonnet
```
````

### States

`open` → `claimed:<host>` → `done` (issue closed) or `failed` (issue stays open). The result is posted as one comment: status, the agent and host, the last 3,500 characters of output, and the ledger run id. A failure includes timeouts, a missing repo, and a refused model.

### Claiming

Runners race safely without a lock service. A runner adds `claimed:<host>` and assigns itself, then reads the issue's label events. The earliest `claimed:*` event wins. A loser removes its own label and moves on. Each machine runs at most one task per agent at a time, enforced by a lock file in `~/.kun/dispatch/`.

### Billing

Subscription only. A task whose model or lane matches `fable`, `mythos` or `escalate` is refused with a `failed` comment and never runs. Without a model, the agent uses the lane's model from `engine.json` (default lane `build`). Claude tasks go through `kun-claude.sh`, so the run lands in the job ledger as `dispatch:claude`.

## Use

```bash
kun-dispatch "Reply with PONG" --to claude --machine abdout
kun-dispatch "Refactor the table atom" --to codex --repo codebase --lane build --timeout 45
kun-dispatch run         # one runner pass, by hand
kun-dispatch heartbeat   # write this machine's status
kun-dispatch install     # write the launchd plist / systemd timer (does not load it)
```

`send.mjs` ensures the labels exist and prints the issue URL.

## Agents

| Agent | Headless command |
| --- | --- |
| `claude` | `kun-claude.sh -p <brief> --dangerously-skip-permissions --model <lane model>` |
| `fcc` | `kun-free.sh -p <brief>` (Claude Code on free models) |
| `codex` | `codex exec --dangerously-bypass-approvals-and-sandbox -C <cwd> <brief>` |
| `opencode` | `opencode run --dir <cwd> <brief>` |
| `agy` | `agy -p <brief> --dangerously-skip-permissions` |
| `hermes` | `hermes -z <brief>` |

A runner only offers the agents installed on its machine (`launchers.json` plus `which`).

## Running the runner

`install.mjs` writes `~/Library/LaunchAgents/com.databayt.dispatch-runner.plist` (every 120 seconds, log at `~/.kun/dispatch/runner.log`) or a systemd user timer on Linux, and prints the command to load it. It never loads it itself.

`heartbeat.mjs` writes `.claude/state/machines/<login>.json`: agents and versions, the last runner pass, and this machine's queue depth. It is not committed by the runner; the memory sync lane picks it up.

Files: `.claude/scripts/dispatch/` (`send`, `runner`, `install`, `heartbeat`, `lib`, tests) and `.claude/bin/kun-dispatch`.
