A lane is a kind of work with a fixed model and a fixed effort. Every agent and every skill in the engine names one lane, in one word, in its frontmatter. Nobody sets a model by hand: a script reads the table below and writes the settings Claude Code actually applies.

## The table

| Lane | Model | Effort | How it runs |
| --- | --- | --- | --- |
| `script` | none | — | a script — zero tokens |
| `mechanical` | haiku | low | a forked skill: no conversation history, under 100K tokens |
| `lookup` | haiku | low | the Explore agent |
| `research` | sonnet | low | Explore with a written brief |
| `build` | sonnet | medium | a build agent with a written brief |
| `judge` | opus | high | the main loop or an opus agent |
| `captain` | opus | xhigh | the main loop, attended |
| `escalate` | fable | xhigh | by hand, attended only — never unattended |

The table lives in `.claude/engine.json` under `lanes`. Change a row, run `node .claude/scripts/compile-lanes.mjs`, and everything on that lane changes with it.

## What a lane writes

| For | It writes | Why |
| --- | --- | --- |
| an agent | `model` and `effort` | applied when the agent starts |
| a skill on `mechanical`, `lookup` or `research` | `context: fork`, `model`, `effort` | the skill runs as a separate agent with no conversation history, on the lane's model |
| a skill on `build`, `judge` or `captain` | `effort` only | switching model in the middle of a conversation throws away the prompt cache, so these stay on the session's model and hand heavy steps to an agent |

## Where it is enforced

1. **Frontmatter.** Claude Code applies an agent's model when it starts it, and forks a skill onto its lane's model when the skill is invoked.
2. **Explore.** The engine ships its own `Explore` agent on Haiku; the built-in one ran on the session's model.
3. **The route hint.** A short prompt that opens with a fork-lane skill (`dev`, `health`, `watch`) is told to invoke the skill rather than do the work in the main loop.
4. **The route guard.** A subagent call that names no model gets the build lane's; a call that names Fable is refused.
5. **Headless runs.** A scheduled run takes its model from its job's lane and can never be Fable.
6. **The lint.** `lint-contracts.mjs` fails on an agent or skill with no lane, or with a model or effort set by hand.

One call can still ask for more: naming a model on a single agent call overrides the lane for that call.
